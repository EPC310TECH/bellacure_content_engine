The MVP provides a technician media dashboard and a leadership job/review dashboard. Its no-credentials preview uses clearly labeled sample data and does not persist demo uploads. With Supabase configured, uploads use a private bucket and database-enforced location policies. A separately run Node worker validates image/MP4 signatures, creates private JPEG previews without altering originals, and records retry/error status. It does not generate a finished video. Stripe billing, AI video composition, and TikTok publishing are not connected.

## Local setup

1. Create a Supabase project.
2. Disable public user sign-ups in Supabase Auth settings. Require confirmed email addresses and strong passwords for invited users. Run all SQL files in `supabase/migrations/` in filename order in the Supabase SQL Editor, or link the CLI and apply the migrations.
3. Create the initial leadership user in Supabase Auth. Edit `supabase/bootstrap.sql` with that user's email, then run it in the SQL Editor. The script provisions Beverly Hills, Brentwood Village, Larchmont Village, Santa Monica, South Bay, Studio City, and Sunset, plus the shared 18-cycle theme schedule, editorial hooks, event anchors, and research briefs.

For an existing project that already has the earlier migrations, run `20261007034925_add_content_theme_schedule.sql`, then `20261007040553_add_theme_research_briefs.sql`, in that order. Rerun the updated `supabase/bootstrap.sql` to seed or refresh all 126 location-cycle entries and their research briefs. Do not rerun the older, non-idempotent migrations. Approximate cultural dates and the stated research windows are tracked separately from the existing shoot schedule, which starts October 6, 2026 and repeats every 21 days.
4. For the media worker, apply `20261007052957_add_media_processing_worker_state.sql` after the other migrations. Install FFmpeg on the private worker host and install the web dependencies with `npm ci`.
5. Copy the Supabase project URL and service-role key into the worker host's secret environment as `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`, then run `npm run worker` from `web/`. Keep this key on the private worker only; never use it in the browser or put it in a `NEXT_PUBLIC_` variable. The worker claims one job at a time, verifies content signatures and recorded file size, extracts/normalizes a JPEG preview, and retries failures up to three times. Run it under a process supervisor for continuous work.
6. Copy `.env.example` to `.env.local` and fill in the Supabase project URL and publishable key. The publishable key is intended for browser use; never place a Supabase secret or service-role key in a `NEXT_PUBLIC_` variable.
7. From this directory, run `npm run dev` and open the local address printed by Next.js. Sign in with the leadership account or a technician account added to `location_memberships`.

The migrations create the private `salon-media` bucket, location-scoped RLS policies, upload/job metadata, a membership-protected content schedule with editorial hooks and timely research prompts, retry-safe media processing fields and service-role-only worker functions, and the generated-video review history. Users can upload JPG, PNG, WebP, and MP4 files up to 50 MB after confirming they have permission to use the media. Uploads are stored in paths scoped to location and uploader; client roles cannot alter job state or schedule entries. The worker verifies media signatures, checks recorded sizes, and writes an idempotent derived JPEG under a separate path; originals remain unchanged. MP4 files currently produce a still-frame preview only. No background removal, AI alterations, generated videos, or spoken/text content are created by this worker. The review function requires a generated video and records every approval, rejection, or request for changes. Approved videos are for manual export only. The calendar shows planned content themes, not customer appointment bookings; dates do not trigger generation or research jobs.
